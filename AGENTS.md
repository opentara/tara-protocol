# Working on TARA Protocol

Read README.md, the protocol overview and the dated ODE review before proposing changes.

- Keep TARA general: people, AI agents, collectives and affected living systems. Do not collapse it into one domain's object model.
- Preserve unknowns, disagreements, absent representation, authority boundaries and prior commitments. A forecast is not consent or permission.
- One bounded step may have one leading focus; other constraints remain visible.
- Distinguish a conceptual proposal, a description contract, a structural check, observed behavior and demonstrated effects.
- Keep published practice versions explicit. A skill is guidance, not enforced governance or proof of capability.
- Pin upstream reviews to a tag and commit. Read the current contracts before carrying historical gap claims forward. Do not change ODE automatically.
- Preserve source status and evidence when summarizing or transferring context. Do not rewrite history to make a failed or unauthorized attempt appear admissible.
- Publish only the files listed in `public-files.json`. Do not copy private archives, native personal profiles, credentials, internal correspondence or local filesystem paths into this repository.
- Run `python3 tools/check.py` after edits. It checks structure, local links and publication boundaries, not semantic adequacy or behavior.
- License selection, normative releases and runtime guarantees require separate explicit decisions; do not infer them from a repository commit.
